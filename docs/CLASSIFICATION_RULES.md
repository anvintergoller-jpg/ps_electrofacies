# Правила классификации формы аномалий ПС

**Версия:** 2.1
**Дата:** 2026-09-30
**Статус:** актуально (после ревизии H.5)

## 1. Назначение

Документ описывает правила классификации формы аномалии ПС
для каждого коллекторного интервала, выделенного на шаге
сегментации.

Реализация — `src/domain/classify_form.py`.
Все числовые параметры — в `config/config.yaml`, секция `classification`
(правила формы) и секция `reservoir` (общий порог коллектора).

См. также:
- `docs/DECISIONS_LOG.md`, ADR-001 (система типов сокращена до 6).
- `docs/DECISIONS_LOG.md`, ADR-002 (доработка критериев отложена).
- `docs/ARCHITECTURE.md` — карта модулей.

## 2. Что классифицируем

Классификации подлежат **все интервалы `reservoir`** из таблицы
сегментации, у которых мощность ≥ 1 м в абсолютных отметках
(параметр `reservoir.min_thickness_tvdss`).

Интервалы `non_reservoir` (глина) не классифицируются — их форма
не несёт геологического смысла для типизации коллектора.

Микроинтервалы < 1 м присоединяются к соседним на шаге сегментации
и в классификацию не попадают.

## 3. Опорные точки

Для каждого интервала `reservoir` (≥ 1 м) вычисляются три средних
по **сглаженной** кривой `aSP`:

| Поле      | Смысл                                              |
|-----------|----------------------------------------------------|
| `sp_top`  | Среднее в верхних 15% мощности интервала           |
| `sp_mid`  | Среднее в центральных 15% мощности                 |
| `sp_bot`  | Среднее в нижних 15% мощности                      |

**Доли, а не фиксированные точки.** Параметр `edge_frac` в config,
стартово 0.15. Масштабируется одинаково для интервалов любой
мощности.

**Сглаживание.** Окно `preprocessing.smooth_window` (стартово 5 точек
= 0.5 м при шаге 0.1 м). Используется та же функция `smooth()`,
что в сегментации и литопрофиле.

**Минимум данных.** Если `n_points < classification.min_points`
(по умолчанию 5) → тип `uncertain`, reason = «мало точек».

**Шкала.** Все значения — в **aSP** (alpha-PS): 0 = глина,
1 = чистый песчаник. Классическая геофизическая конвенция,
согласованная с кривой SP в Petrel.

## 4. Типы аномалий

| Тип                 | Геологический смысл                                       |
|---------------------|-----------------------------------------------------------|
| `bell`              | Колокол — регрессия, устье канала, конус выноса           |
| `funnel`            | Воронка — трансгрессия, бар, пляж                         |
| `cylinder`          | Цилиндр — однородный песчаник, массивное русло            |
| `trapezoid-middle`  | Трапеция с плато в середине (линза, переслаивание)        |
| `symmetric`         | Симметричная плавная чаша (линза)                         |
| `v-shape`           | Острый угол с песчаным пиком в центре (линза острая)      |
| `uncertain`         | Форма не определена (в т. ч. возможное переслаивание)     |

Всего — **7 типов**.

Типы `trapezoid-top` и `trapezoid-bottom` **исключены**
(см. ADR-001): они не отличались от `bell` и `funnel` по трём
опорам надёжно.

## 5. Правила классификации

Порядок проверок **важен**. Идём от специфичного к общему.
Полная реализация — в `src/domain/classify_form.py`.

### 5.1. Обозначения и знаки

Пусть:
- `diff_top_bot = sp_top − sp_bot`
- `diff_top_mid = sp_top − sp_mid`
- `diff_bot_mid = sp_bot − sp_mid`

**aSP:**
- **Высокое значение** (близко к 1) = песчаник.
- **Низкое значение** (близко к 0) = глина.

Отсюда:
- **bell** (глина сверху, песок снизу): `diff_top_bot < 0`.
- **funnel** (песок сверху, глина снизу): `diff_top_bot > 0`.
- **cylinder** (ровный песок сверху донизу): все три опоры высокие,
  `|diff_top_bot|` мал.
- **symmetric / v-shape / trapezoid-middle** (песок в центре, глина
  по краям): `sp_mid` заметно выше `sp_top` и `sp_bot`.

### 5.2. Пороги (config.yaml)

Секция `classification`:

| Параметр                | Стартовое значение | Смысл                                 |
|-------------------------|--------------------|---------------------------------------|
| `edge_frac`             | 0.15               | Доля мощности для опор               |
| `threshold_diff`        | 0.20               | Порог «верх vs низ» (bell/funnel)     |
| `plateau_threshold`     | 0.10               | Порог «плато» между опорами           |
| `slope_threshold`       | 0.20               | Порог «наклона» между опорами         |
| `core_threshold`        | 0.05               | Ширина ядра вокруг `sp_mid`           |
| `frac_core_trapezoid`   | 0.40               | Порог `frac_core` для trapezoid-middle|
| `frac_core_v_shape`     | 0.15               | Порог `frac_core` для v-shape         |
| `min_points`            | 5                  | Мин. число точек                      |

Секция `reservoir`:

| Параметр                | Стартовое значение | Смысл                                 |
|-------------------------|--------------------|---------------------------------------|
| `cutoff`                | 0.40               | Порог коллектора по aSP               |

**Значения — стартовые.** Перекалибровка — после накопления
10+ скважин и ручной разметки (см. ADR-002).

### 5.3. Проверки в порядке

**Шаг 1. Мало данных.**
Если `n_points < min_points`:
- Тип: `uncertain`, confidence: 0.0.
- Reason: «мало точек (n_points)».

**Шаг 2. M-форма (переслаивание).**
Условие:
- `sp_top > cutoff` И `sp_bot > cutoff` (кровля и подошва —
  в песчаной зоне),
- `sp_mid < cutoff − slope_threshold` (центр — в глинистой).

Тип: `uncertain`, confidence: 0.30.
Reason: «возможно, переслаивание — проверьте сегментацию».

**Шаг 3. Цилиндр.**
Условие:
- все три опоры > cutoff (в песчаной зоне),
- `|diff_top_bot| < threshold_diff` (верх ≈ низ),
- `frac_core ≥ frac_core_trapezoid` (широкое ядро песка).

Тип: `cylinder`.
Confidence: `min(1.0, frac_core × 1.2)`.
Reason: «ровное плато на песчаном уровне».

**Шаг 4. Глина — песок — глина.**
Условие:
- `|diff_top_bot| < threshold_diff` (верх ≈ низ),
- `sp_mid > sp_top + slope_threshold` И
  `sp_mid > sp_bot + slope_threshold` (центр заметно песчанее).

Разделение по `frac_core` (ширина ядра вокруг sp_mid):

| `frac_core` | Тип | Reason |
|---|---|---|
| ≥ frac_core_trapezoid | `trapezoid-middle` | широкое плато песка в середине |
| frac_core_v_shape .. frac_core_trapezoid | `symmetric` | плавная чаша (парабола) |
| < frac_core_v_shape | `v-shape` | острый угол, песчаный пик |

Confidence — зависит от frac_core (см. код).

**Шаг 5. Bell.**
Условие: `diff_top_bot < −threshold_diff` (верх глинистее низа).
- Тип: `bell`, confidence: `min(1.0, |diff_top_bot|/threshold_diff − 0.5)`.
- Reason: «глина сверху, песок снизу».

**Шаг 6. Funnel.**
Условие: `diff_top_bot > threshold_diff` (верх песчанее низа).
- Тип: `funnel`, confidence: `min(1.0, diff_top_bot/threshold_diff − 0.5)`.
- Reason: «песок сверху, глина снизу».

**Шаг 7. Иначе — uncertain.**
- Тип: `uncertain`, confidence: 0.30.
- Reason: «ни одно правило не сработало».

## 6. Ключевой признак `frac_core`

`frac_core` = доля точек интервала, у которых `|aSP − sp_mid| < core_threshold`.

- **Большая** (≥ 0.40) → широкое плато вокруг `sp_mid` (trapezoid-middle).
- **Средняя** (0.15 – 0.40) → плавная чаша (symmetric).
- **Малая** (< 0.15) → острый угол (v-shape).

Этот признак — основной разделитель трёх форм с одинаковыми
опорами. Работает устойчиво на интервалах длиной ≥ 20 точек.

**Ограничение.** На коротких интервалах (10–15 точек) `frac_core`
нестабилен — см. ADR-002. При накоплении выборки признак
пересматривается вместе с другими критериями.

## 7. Уверенность (confidence)

Формулы:
- cylinder: `min(1.0, frac_core × 1.2)`;
- trapezoid-middle, symmetric: `min(1.0, 0.5 + frac_core)`;
- v-shape: `min(1.0, 0.5 + (frac_core_v_shape − frac_core) × 3)`;
- bell, funnel: `min(1.0, |diff_top_bot| / threshold_diff − 0.5)`;
- uncertain (по любому сценарию): фиксированные 0.30;
- non_reservoir: 1.0 (по определению — форма не нужна).

Confidence — **не откалиброванная вероятность**, а эвристическая
оценка «насколько выражена форма». Для фильтрации и сортировки,
не для принятия решений.

## 8. Оговорки и правила изменений

1. **Все пороги в config.** Если геолог считает, что для его
   района `threshold_diff` должен быть 0.3 — меняет одну строку
   в `config.yaml` и перезапускает пайплайн. Код не правится.

2. **Версионирование правил.** Текущая версия — **2.1**.
   Результаты классификации содержат `rules_version`.
   Обновляем версию при изменении методики (не порогов).

3. **Классификация формы ≠ геологический диагноз.**
   `bell` — форма кривой ПС, не «устье канала». Диагноз — комплекс
   методов.

4. **Без ГК.** Классификация — только по `aSP`. `GK_norm` считаем
   и сохраняем для будущего. Включение в правила — отдельный шаг
   (мультиметодность).

5. **Одна скважина не выборка.** Все текущие значения порогов
   откалиброваны на 5 скважинах одного района. Не догма.

6. **Доработка критериев отложена** (ADR-002). Возврат — после
   набора ≥ 5 скважин с ручной разметкой. До этого не крутим
   пороги «на глаз».

7. **M-форма (переслаивание)** — не отдельный тип, а флаг.
   Такие интервалы попадают в `uncertain` с явным reason.
