## 1. Что за проект

**ps_electrofacies** — Python-программа для типизации пластов
по кривой ПС (SP) методом электрофациального анализа.
Применяется в геологии нефти и газа для характеристики разреза,
корреляции скважин, построения карт.

- Репозиторий: https://github.com/anvintergoller-jpg/ps_electrofacies
  (публичный, но доступа к нему у ассистента нет — файлы нужно
  присылать в чат).
- Локально: `C:\Py_scripts\ps_electrofacies`.
- Стек: Python 3.14, VS Code, Git/GitHub. numpy, pandas,
  matplotlib, lasio, openpyxl, pyyaml.

**Пользователь:** геолог-петрофизик, новичок в программировании,
учится «вайбкодингу с умом». Особенности работы с ним:

- Нужны подробные комментарии в коде и методике.
- Сначала документ — потом код.
- Не менять старое без причины.
- Все параметры — в `config.yaml`, не в коде.
- Каждая итерация — commit + push в Git.

## 3. Ключевые методические решения

Короткий список того, что уже зафиксировано в ADR, чтобы не
пересматривать заново:

- **Единица анализа — пласт-контейнер** (БС9, БС10-1, …),
  а не разрез скважины (ADR-003).
- **Шкала aSP** (alpha-PS): 0 = глина, 1 = песок (ADR-006).
  Заменила прежнюю `SP_norm` (0 = песок, 1 = глина).
- **GK_norm:** 0 = песок, 1 = глина. Осталась как была.
- **Нормализация:** перцентили 2/98, для каждой скважины
  отдельно, внутри рабочего интервала (ADR-007). Сглаживание
  исходной SP не применяется.
- **Порог коллектора:** `aSP > 0.4` (Муромцев).
- **7 типов формы** (ADR-001). Убраны trapezoid-top/bottom.
- **Размер интервала:** доля мощности интервала в мощности
  контейнера (не перцентили выборки).
- **Положение:** по центроиду в контейнере (top/middle/bottom).
- **Сводная типизация:** container_type = `{single/multi/no-sand}-
  {form}-{size}-{position}` (ADR-004).
- **Батч:** `wells: "auto"` в config или явный список (ADR-005).
- **Ревизия H.5:** единые секции `preprocessing` (smooth_window)
  и `reservoir` (cutoff, min_thickness_tvdss) в config (ADR-008).
- **Доработка критериев формы отложена** (ADR-002) — до набора
  выборки и ручной разметки.

## 4. Как мы работаем (формат взаимодействия)

**Формат патчей:**
- Меняется 1–3 строки → патч (конкретные «найди / замени»).
- Меняется структура файла или несколько мест → полный файл.
- Ассистент предупреждает: «пока не запускать пайплайн, потому что...»

**Ритм:**
1. Пользователь применяет патч, запускает, скидывает лог.
2. Ассистент анализирует, сравнивает с предыдущим запуском.
3. Обсуждаем результат, решаем следующий шаг.
4. Коммит после значимой итерации.

**При работе с логами:** ассистент смотрит на изменение ключевых
чисел между запусками (формы, NTG, container_type). Если что-то
изменилось «не туда» — ищем причину, не оставляем как есть.

**При работе с кодом:** перед ревизией ассистент может попросить
полные файлы (не только diff), чтобы поймать скрытые баги.

**Про docs:** при обновлении документа — полная замена файла
целиком, не патч. Документы короткие, лучше переписать целиком,
чем рисковать потерей контекста.

## 5. Что обсудить в новом чате

**Основные вопросы для начала работы:**

1. **Сколько скважин добавляем** — 5 или сразу 10–15.
2. **Откуда** — те же районы, что и текущие, или из разных зон.
3. **План** — последовательность: добавить → прогнать →
   посмотреть → решить про разметку.
4. **Ручная разметка** — как оформить шаблон, что размечать
   (только форму? или размер/положение тоже?).

**Плюс открытый вопрос:** что делать с 5 уже имеющимися скважинами,
если новые окажутся из другой зоны — считать одной выборкой
или разделить по районам.
