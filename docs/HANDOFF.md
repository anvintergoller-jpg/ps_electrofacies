### 2.2. В разработке (v3.0) — ГЛАВНОЕ

**Методика классификации формы полностью перерабатывается.**

Причина: v2.x опирается на три опорные точки и пороги, что даёт
привязку к выборке. v3.0 переходит к **структурному описанию
аномалии** — через элементы (кровля / плато / подошва).

**Документ:** `docs/CLASSIFICATION_RULES_v3.md` — черновик готов,
все 14 разделов. **Читать первым делом.**

**Ключевые идеи v3.0:**

- Аномалия = кровля + плато (опц.) + подошва.
- Каждый элемент имеет: тип (`М` мгновенный / `Н` наклонный /
  `К` константа), длину (м и доля), модификатор (пологий / зубчатый).
- **7 форм:** bell, funnel, v-shape, trapezoid-top, trapezoid-bottom,
  trapezoid-middle, cylinder + unknown-shape.
- **Определение формы:**
  - с плато — по типам границ: cylinder = Кр(М)+Пл+Пд(М), и т. д.
  - без плато — по положению максимума aSP (`max_position`):
    - у кровли (< 0.15) → funnel,
    - у подошвы (> 0.85) → bell,
    - в середине → v-shape.
- **Дискретный лог `aSP_disc`** — 5 классов Муромцева с границами
  `(lower, upper]`. Используется для поиска плато, выделения
  аномалий (класс ≥ 2), определения контекста.
- **Плато определяется по дискретному логу** — длинный участок
  одного класса (≥ 1 м).
- **`max_position`** — новый ключевой признак для треугольников.
- **`container_state`:** single-anomaly / multi-anomaly /
  interbedded / no-sand.
- **Метка пласта:** `{N}-{form|mixed}-{size}-{position}`.
- **Пороги v3.0:** `boundary_frac = 0.15`,
  `min_plateau_thickness_tvdss = 1.0`,
  `min_class_thickness_tvdss = 0.5`.

**Реализация — следующий шаг. По порядку:**

1. Расчёт `aSP_disc` (колонка в `dataset.csv`).
2. Функция разбиения интервала на элементы.
3. Классификатор `classify_form_v3.py` — 7 типов.
4. Интеграция в пайплайн.

**Формат проверки:** сначала прогон на пилоте 227_2263 (7 интервалов),
геолог смотрит глазами и сравнивает с формой на планшете. Потом
5 скважин. Ручная разметка — на этапе 3 (после набора выборки).

**Стратегия внедрения:** параллельный модуль `classify_form_v3.py`
рядом с текущим `classify_form.py`. Старое работает, новое
проверяется. После стабилизации — переключаем.

## 3. Ключевые методические решения (ADR)

Короткий список. Подробно — в `DECISIONS_LOG.md`.

- **Единица анализа — пласт-контейнер** (не разрез) — ADR-003.
- **Шкала aSP** (0 = глина, 1 = песок), заменила SP_norm — ADR-006.
- **Нормализация 2/98** перцентили, для каждой скважины отдельно —
  ADR-007.
- **Порог коллектора:** `aSP > 0.4` (Муромцев).
- **Батч:** `wells: "auto"` или явный список — ADR-005.
- **Ревизия H.5:** единые секции `preprocessing` и `reservoir`
  в config — ADR-008.
- **v3.0 — замена парадигмы классификации формы** (в разработке).

## 4. Как мы работаем

**Формат патчей:**
- 1–3 строки → патч (найди / замени).
- Структурные изменения или много мест → полный файл.
- Ассистент предупреждает: «пока не запускать пайплайн, потому что...»

**Ритм:**
1. Применяешь патч, запускаешь, скидываешь лог.
2. Ассистент анализирует, сравнивает с предыдущим запуском.
3. Обсуждаем результат, решаем следующий шаг.
4. Коммит после значимой итерации.

**При работе с кодом:**
- Правки только по коду, который прислан. **Не восстанавливать
  из документов** — синтаксис будет другой, сломает совместимость.
- Перед ревизией — просить полные файлы (не только diff).

**При работе с docs:**
- Полная замена файла, не патч.
- Каждая новая версия — обновление даты и версии в шапке.

**Особенно:** если ассистент видит проблему или противоречие —
говорить прямо. Пользователь сам просил «бить тревогу».
