# Правила классификации формы аномалий ПС (v3.0)

**Версия:** 3.0-draft
**Дата:** 2026-10-01
**Статус:** черновик, обсуждается

**Предыдущая версия:** 2.1 (см. `CLASSIFICATION_RULES.md`).
**Причина переработки:** методика v2.x опиралась на три опорные точки
(sp_top / sp_mid / sp_bot) и набор порогов между ними. Это давало
привязку к конкретной выборке и неустойчивость при смене скважин
или параметров нормализации. v3.0 переходит к **структурному
описанию аномалии** через её элементы — это универсальнее и не
зависит от калибровки порогов под выборку.

## 1. Введение и цель

### 1.1. Что меняется относительно v2.1

**Было (v2.x):**
- Опоры на трёх точках (sp_top, sp_mid, sp_bot).
- Пороги `threshold_diff`, `slope_threshold`, `frac_core` и т. п.
- Семь типов, определяемых по формулам от опор.
- Много `uncertain` — свалка для всего непонятного.

**Станет (v3.0):**
- Аномалия описывается через **элементы**: кровля, плато, подошва.
- У каждого элемента — **тип** (константа / мгновенный / наклонный /
  отсутствует), **длина**, **градиент** (справочно),
  **модификатор** (пологий / зубчатый).
- Тип формы — это **комбинация типов элементов**.
- `unknown-shape` — осознанный сигнал, а не свалка.

### 1.2. Зачем переработка

- **Универсальность.** Критерии не привязаны к порогам, откалиброванным
  на конкретной выборке.
- **Прозрачность.** Геолог смотрит на кривую и видит: «кровля резкая,
  плато длинное, подошва пологая» — это и есть описание аномалии.
- **Расширяемость.** Новые формы добавляются как новые комбинации
  элементов, без переопределения порогов.
- **Осмысленный `unknown-shape`.** Если аномалия не подходит ни под
  один шаблон — это сигнал. Если таких много — методика требует
  пересмотра.

### 1.3. Что НЕ входит в v3.0

- Детекция тонкого переслаивания (< 1 м). Отложено.
- Кластеризация и ML. Только правила.
- Учёт ГК. Только aSP. `GK_norm` считаем и храним, но в правила
  не включаем.
- Полная автоматизация. Часть параметров — стартовые, адаптируются
  по результатам на реальных данных.

## 2. Система координат и единицы

### 2.1. Ось глубины — TVDSS

Все расчёты формы выполняются в **TVDSS** (абсолютные отметки, м).
Причина — угол наклона ствола не должен искажать форму аномалии.

**Точки каротажа остаются «как есть»** — с их MD-шагом. Никакого
пересемплирования на равномерную сетку TVDSS. Между соседними
точками считаем Δdepth_tvdss — он может быть неравномерным, это
нормально. Формулы производных и длин работают с реальными
приращениями.

Обозначения:
- `depth_tvdss` — глубина точки в АО, м;
- `aSP` — нормированный ПС (0 = глина, 1 = песок);
- производные и длины — по `depth_tvdss`.

### 2.2. Шкала aSP

`aSP` (alpha-PS) — классический приведённый ПС:
- **0** = чистая глина;
- **1** = чистый песчаник.

Расчёт — в `src/preprocessing/normalization.py`. Перцентили 2/98,
для каждой скважины отдельно, внутри рабочего интервала
(см. ADR-007).

### 2.3. Дискретный лог aSP_disc

Для предварительного выделения аномалий используется дискретный
лог `aSP_disc` с 5 классами по Муромцеву.

**Правило границ:** интервал класса `(lower, upper]` — нижняя
граница не включается, верхняя включается.

| Класс | Условие | Литология |
|---|---|---|
| 0 | aSP ≤ 0.2 | глина |
| 1 | 0.2 < aSP ≤ 0.4 | алевролит глинистый |
| 2 | 0.4 < aSP ≤ 0.6 | алевролит / песчаник |
| 3 | 0.6 < aSP ≤ 0.8 | песчаник среднезернистый |
| 4 | aSP > 0.8 | песчаник крупнозернистый |

**Роль дискретного лога:**
- быстрое выделение **зон аномалии** (класс ≥ 2);
- поиск **кандидатов в плато** (длинные участки одного класса);
- уточнение **границ элементов**.

**Ограничение.** Дискретизация теряет информацию: плавный переход
и резкий прыжок через класс выглядят одинаково. Поэтому
**уточнение формы всегда по сырому aSP**. Дискретный лог —
вспомогательный.

### 2.4. Минимальный интервал дискретного класса

Если после дискретизации участок одного класса короче
**`min_class_thickness_tvdss`** (стартово 0.5 м) — присоединяется
к соседнему. Аналог `min_thickness_tvdss` для сегментации.

Параметр в `config.yaml`.

## 3. Терминология

### 3.1. Элемент аномалии

Аномалия состоит из **двух обязательных** элементов и **одного
опционального**:

| Элемент | Обязательный? | Что описывает |
|---|---|---|
| **Кровля** | да | переход от неколлектора (сверху) к песчанику |
| **Плато** | нет | участок стабильного aSP в средней части |
| **Подошва** | да | переход от песчаника к неколлектору (снизу) |

**Плато — интегральное понятие.** Внутри аномалии может быть
несколько участков одного класса αПС (2 / 3 / 4) длиной ≥
`min_plateau_thickness_tvdss`. Все участки **одного
доминирующего класса** объединяются в одно **интегральное плато**.
Участки других классов не поглощаются — они становятся частью
кровли или подошвы.

**Доминирующий класс плато** — тот, у которого суммарная мощность
плато-кандидатов максимальна. Тай-брейк при равенстве — по
среднему aSP (выше = чище песок).

Если плато есть — аномалия состоит из трёх элементов (кровля,
плато, подошва). Если плато нет — только из кровли и подошвы
(«треугольник»).

### 3.2. Типы элементов

Каждый элемент классифицируется по **типу**. Тип описывает
**структуру** элемента (как меняется aSP по глубине).

| Тип | Что означает |
|---|---|
| **Константа** | aSP стабилен (в узком коридоре) на протяжении ≥ min_plateau |
| **Мгновенный переход** | изменение aSP занимает < 15% мощности интервала (или < 1 м) |
| **Наклонный переход** | изменение aSP занимает 15–85% мощности интервала |
| **Отсутствует** | элемента нет (например, нет плато) |

**Термин «мгновенный»** выбран вместо «вертикальный» —
параллельность оси Y может путать. «Мгновенный» = быстрое изменение
aSP при малом изменении глубины.

**Важно:** «константа» — это тип элемента, а не сам элемент.
Элемент называется «плато», его тип может быть «константа».
Не путать.

### 3.3. Модификаторы элементов

Помимо типа, каждый элемент имеет **модификатор**, описывающий
степень его гладкости:

| Модификатор | Что означает |
|---|---|
| **Пологий** | линия гладкая, знак производной не меняется (или меняется редко) |
| **Зубчатый** | есть локальные пики — знак производной меняется часто |

**Определение зубчатого элемента:**

> Элемент считается **зубчатым**, если доля точек, отклоняющихся
> от локального среднего больше чем на `zigzag_threshold`
> (стартово 0.05 единиц aSP), превышает `zigzag_fraction`
> (стартово 0.20). Иначе элемент — пологий.

Пороги — в `config.yaml`, адаптируются по результатам.

### 3.4. Другие термины

- **Плато** — элемент аномалии, а не «плоская линия» любой длины.
  Обязательно ≥ `min_plateau_thickness_tvdss` (стартово 1 м).
- **Аномалия** — интервал внутри пласта, где aSP > `reservoir.cutoff`
  (стартово 0.4). Совпадает с определением `reservoir` из v2.x.
- **Контекст** — тип породы над и под аномалией (по дискретному логу).

## 4. Структура аномалии

### 4.1. Порядок элементов

Аномалия всегда читается **сверху вниз** (по возрастанию глубины):

```
┌─────────────────────────────────┐  ← кровля контейнера (пласта)
│   неколлектор (контекст)        │
├─────────────────────────────────┤  ← top_tvdss аномалии
│                                 │
│   КРОВЛЯ (обязательный)         │
│   (мгновенный / наклонный)      │
│                                 │
├─────────────────────────────────┤
│                                 │
│   ПЛАТО (опциональный)          │
│   (тип: константа)              │
│                                 │
├─────────────────────────────────┤
│                                 │
│   ПОДОШВА (обязательный)        │
│   (мгновенный / наклонный)      │
│                                 │
├─────────────────────────────────┤  ← bottom_tvdss аномалии
│   неколлектор (контекст)        │
├─────────────────────────────────┤  ← подошва контейнера (пласта)
└─────────────────────────────────┘
```

### 4.2. Порядок элементов — строго

Порядок фиксирован:
1. Кровля (всегда сверху).
2. Плато (если есть — в середине).
3. Подошва (всегда снизу).

**Кровля не может быть ниже плато.** Плато не может быть ниже
подошвы. Если данные дают «аномальный» порядок — значит,
структура сложнее, чем «кровля-плато-подошва». Такие случаи
уходят в `unknown-shape`.

### 4.3. Границы аномалии

Границы аномалии (`top_tvdss` и `bottom_tvdss`) — **готовые границы
reservoir-интервала из сегментации**. Они определены на шаге
сегментации по порогу `reservoir.cutoff`.

**В v3.0 мы их не переопределяем и не уточняем.** Задача v3.0 —
описать форму внутри готовых границ. Сегментация и классификация
формы — независимые шаги.

Возможно, в будущем понадобится уточнение границ — но не сейчас.
Сначала посмотрим, как работают элементы на текущих границах.

### 4.4. Контекст аномалии

Над и под аномалией — неколлектор. Его тип определяется по
дискретному логу:

| Тип контекста | Дискретный класс |
|---|---|
| **Глина** | 0 (aSP ≤ 0.2) |
| **Алевролит глинистый** | 1 (0.2 < aSP ≤ 0.4) |
| **Отсутствует** | аномалия начинается/кончается на кровле/подошве пласта |

Контекст хранится как два отдельных признака:
- `upper_context` (что над аномалией);
- `lower_context` (что под аномалией).

Это **не тип аномалии**, а её **окружение**. Используется в анализе,
но не в определении формы.

### 4.5. Плато — с числовым значением и классом

Плато описывается не только длиной, но и **средним значением aSP**
плюс **классом αПС**. Это дополнительная характеристика качества
коллектора:

- плато со средним aSP 0.85 → класс 4 (чистый песчаник);
- плато со средним aSP 0.55 → класс 2 (алевролит / песчаник).

Хранятся два признака:
- `plateau_mean_asp` — среднее значение aSP на плато;
- `plateau_class` — класс αПС (2, 3 или 4).

Оба участвуют в анализе качества, но **не в определении типа формы**.
Форма остаётся формой, независимо от абсолютного уровня.
## 5. Признаки элементов

Для каждого из трёх элементов аномалии (кровля, плато, подошва)
вычисляется набор признаков. Часть признаков — общие, часть —
специфичные для элемента.

### 5.1. Обозначения элементов

- **Кр** — кровля (кровельная линия);
- **Пл** — плато (плато аномалии);
- **Пд** — подошва (подошвенная линия).

### 5.2. Общие признаки (для всех элементов)

| Признак | Тип | Что означает |
|---|---|---|
| `type` | str | Тип элемента: `М` / `Н` / `К` / `abs` |
| `length_m` | float | Длина элемента в метрах (TVDSS) |
| `length_frac` | float | Доля от мощности интервала (0..1) |
| `mean_gradient` | float | Средний градиент (единицы aSP/м). Справочный |
| `modifier` | str | `пологий` / `зубчатый` |

**Типы элементов:**
- `М` — мгновенный переход;
- `Н` — наклонный переход;
- `К` — константа (только для плато);
- `abs` — отсутствует.

### 5.3. Специфичные признаки

**Для кровли и подошвы** (переходы):

| Признак | Что означает |
|---|---|
| `start_asp` | aSP в начале элемента (со стороны глины) |
| `end_asp` | aSP в конце элемента (со стороны песка) |

Для кровли: `start_asp` ≈ 0.4 (граница), `end_asp` — значение на выходе в песок.
Для подошвы: наоборот.

**Для плато** (если есть):

| Признак | Что означает |
|---|---|
| `plateau_mean_asp` | среднее значение aSP на плато |
| `plateau_class` | класс αПС (2 / 3 / 4) |
| `plateau_trend` | тип внутренней изменчивости (`flat` / `rising` / `falling` / `symmetric`) |

**Фильтр плато-кандидатов.** Плато-кандидат включается в анализ,
только если его средний aSP ≥ `min_plateau_asp` (стартово 0.5).
Это отсекает участки класса 2 на границе коллектора
(asp ~0.45–0.50) — формально они длинные, но по факту это
переходные зоны, а не песчаные плато.

### 5.4. Именование признаков в таблице

Признаки хранятся с префиксами:
- `top_*` — кровля;
- `plateau_*` — плато;
- `bot_*` — подошва.

Пример полного набора:

| Признак | Значение |
|---|---|
| `top_type` | М |
| `top_length_m` | 0.3 |
| `top_length_frac` | 0.06 |
| `top_start_asp` | 0.35 |
| `top_end_asp` | 0.82 |
| `top_modifier` | пологий |
| `plateau_type` | К |
| `plateau_length_m` | 3.5 |
| `plateau_length_frac` | 0.70 |
| `plateau_mean_asp` | 0.78 |
| `plateau_class` | 3 |
| `plateau_trend` | symmetric |
| `plateau_modifier` | пологий |
| `bot_type` | Н |
| `bot_length_m` | 1.2 |
| `bot_length_frac` | 0.24 |
| `bot_start_asp` | 0.82 |
| `bot_end_asp` | 0.38 |
| `bot_modifier` | зубчатый |

## 6. Признаки интервала (сводные)

Помимо признаков отдельных элементов, у каждого интервала
вычисляются **сводные признаки**.

### 6.1. Структурные

| Признак | Тип | Что означает |
|---|---|---|
| `n_elements` | int | Количество элементов: 2 или 3 |
| `has_plateau` | bool | Есть ли плато |
| `plateau_position` | str | `top` / `middle` / `bottom` / `absent` |

**`plateau_position`** определяется по расположению **центра**
плато **внутри аномалии** (не относительно пласта-контейнера):
- `top` — центр в верхней трети аномалии (0–0.33 мощности);
- `middle` — в средней трети (0.33–0.67);
- `bottom` — в нижней трети (0.67–1.0);
- `absent` — плато нет.

Границы аномалии — `top_tvdss` и `bottom_tvdss` из сегментации.

### 6.2. Мощности

| Признак | Что означает |
|---|---|
| `thickness_tvdss` | общая мощность интервала (аномалии) |
| `thickness_top_tvdss` | мощность кровли (= `top_length_m`) |
| `thickness_plateau_tvdss` | мощность плато (= `plateau_length_m`) |
| `thickness_bot_tvdss` | мощность подошвы (= `bot_length_m`) |

Сумма трёх мощностей = `thickness_tvdss` при наличии всех элементов.
Для треугольников (без плато) сумма двух = `thickness_tvdss`.

### 6.3. Симметрия и тренд

Симметрия живёт **на двух уровнях** — не путать.

**Уровень 1. Тип плато — `plateau_trend`.**

Описывает внутреннюю изменчивость плато (по сырому aSP):

| Значение | Что означает |
|---|---|
| `flat` | aSP стоит ровно, тренда нет |
| `rising` | aSP медленно растёт к концу плато |
| `falling` | aSP медленно падает к концу плато |
| `symmetric` | aSP растёт к центру и падает после (или наоборот) |
| `absent` | плато нет |

Это **тип элемента плато**, а не модификатор. «Плато с трендом»
и «плоское плато» — разные вещи.

**Уровень 2. Модификатор интервала — `symmetry_top_bot`.**

Описывает симметрию кровли и подошвы по длине:

| Значение | Что означает |
|---|---|
| `symmetric` | ratio ∈ [0.5, 2.0] — линии примерно равной длины |
| `asymmetric-top` | кровля существенно длиннее подошвы |
| `asymmetric-bot` | подошва существенно длиннее кровли |
| `n/a` | для форм, где неприменимо |

**Где применяется.** Модификатор `symmetry_top_bot` осмыслен
**только для форм с обеими плавными линиями**: `v-shape` и
`trapezoid-middle`. Для остальных форм (bell, funnel,
trapezoid-top, trapezoid-bottom, cylinder) — `n/a`.

**Формула:**

```
ratio = top_length_m / bot_length_m
```

Защита от деления на ноль: если `bot_length_m` близко к 0
(подошва мгновенная), модификатор = `n/a`.

### 6.4. Экстремум

| Признак | Что означает |
|---|---|
| `max_position` | относительное положение точки максимума aSP (0 = кровля, 1 = подошва) |

Используется для разделения треугольников (см. §7.3).
Для интервалов с плато не имеет смысла (`n/a`), потому что
максимум размыт.

### 6.5. Контекст

| Признак | Что означает |
|---|---|
| `upper_context` | тип породы над аномалией |
| `lower_context` | тип породы под аномалией |

Значения: `глина` / `алевролит глинистый` / `отсутствует`
(см. §4.4).

## 7. Типы формы

### 7.1. Обозначения

Для краткости используется структурная запись:

```
<Кр>(<тип>) | <Пл> | <Пд>(<тип>)
```

Где:
- `Кр` — кровля, `<тип>` ∈ {`М`, `Н`};
- `Пл` — плато: `+` (есть) или `–` (нет);
- `Пд` — подошва, `<тип>` ∈ {`М`, `Н`}.

**Типы элементов:**
- `М` — мгновенный переход;
- `Н` — наклонный переход.

**Примеры:**
- `Кр(Н) | – | Пд(М)` — кровля наклонная, плато нет, подошва мгновенная.
- `Кр(М) | + | Пд(М)` — обе мгновенные, плато есть (длинное).

### 7.2. Таблица форм

| Форма | Структура | Что означает |
|---|---|---|
| **bell** | `Кр(Н) ｜ – ｜ Пд(М)` | Плавный вход сверху, резкий выход снизу. Лучший коллектор **внизу**. |
| **funnel** | `Кр(М) ｜ – ｜ Пд(Н)` | Резкий вход сверху, плавный выход снизу. Лучший коллектор **вверху**. |
| **v-shape** | `Кр(Н) ｜ – ｜ Пд(Н)` | Обе линии плавные, плато нет. Треугольник. |
| **trapezoid-top** | `Кр(Н) ｜ + ｜ Пд(М)` | Аналог bell, но с плато. Плавный вход, плато, резкий выход. |
| **trapezoid-bottom** | `Кр(М) ｜ + ｜ Пд(Н)` | Аналог funnel, но с плато. Резкий вход, плато, плавный выход. |
| **trapezoid-middle** | `Кр(Н) ｜ + ｜ Пд(Н)` | Аналог v-shape, но с плато. Обе линии плавные + плато. |
| **cylinder** | `Кр(М) ｜ + ｜ Пд(М)` | Обе линии мгновенные + длинное плато. Прямоугольник. |
| **unknown-shape** | любая другая | Не подходит ни под одну структуру. |

**Логика группировки:**
- **Треугольники (без плато):** bell, funnel, v-shape.
- **Трапеции (с плато):** trapezoid-top, trapezoid-bottom, trapezoid-middle.
- **Прямоугольник (с длинным плато):** cylinder.

Названия `top` / `bottom` в трапециях — **про тип границы**
(какая линия плавная), а не про положение плато:
- `trapezoid-top` — плавная **кровля** (верхняя граница), как у bell;
- `trapezoid-bottom` — плавная **подошва** (нижняя граница), как у funnel;
- `trapezoid-middle` — обе плавные, как у v-shape.

### 7.3. Порядок определения формы

Алгоритм последовательный, от специфичного к общему.

**Шаг 1. Разбить аномалию на элементы.**

- Найти все **плато-кандидаты** — участки одного класса αПС из
  {2, 3, 4} длиной ≥ `min_plateau_thickness_tvdss` (стартово 1 м).
- Определить **доминирующий класс** — тот, у которого суммарная
  мощность плато-кандидатов максимальна. Тай-брейк при равенстве —
  по среднему aSP (выше = чище песок).
- Построить **интегральное плато** — объединение всех плато-
  кандидатов доминирующего класса: от верхней границы первого до
  нижней границы последнего. «Дырки» между плато (короткие участки
  других классов) попадают внутрь интегрального плато.
- Если интегрального плато нет — работаем с треугольником
  (см. шаг 2б).
- Если плато есть: кровля сверху, подошва снизу, плато между ними.
  Границы:
  - `top_tvdss` аномалии — из сегментации;
  - `plateau_top_tvdss` — верх интегрального плато;
  - `plateau_bottom_tvdss` — низ интегрального плато;
  - `bottom_tvdss` аномалии — из сегментации.

**Шаг 2а. Есть плато — определить типы кровли и подошвы.**

Граница считается **мгновенной** (`М`), если её длина
**не превышает обоих порогов**:
length_tvdss ≤ min(boundary_frac × thickness_tvdss, boundary_max_tvdss)

Иначе граница **наклонная** (`Н`).

- Для кровли: `top_length_tvdss = top_tvdss аномалии −
  plateau_top_tvdss`.
- Для подошвы: `bot_length_tvdss = plateau_bottom_tvdss −
  bottom_tvdss аномалии`.

**Шаг 2б. Плато нет — определить тип по положению максимума.**

Для треугольников отдельная проверка границ не нужна — она
выводится из положения максимума aSP.

- Найти точку максимума aSP внутри аномалии.
- Посчитать `max_position = (top_tvdss − max_tvdss) / thickness`.
- Интерпретировать:

| `max_position` | Тип |
|---|---|
| `< boundary_frac` (0.15) | **funnel** (максимум у кровли → кровля мгновенная, подошва наклонная) |
| `> 1 − boundary_frac` (0.85) | **bell** (максимум у подошвы → кровля наклонная, подошва мгновенная) |
| между 0.15 и 0.85 | **v-shape** (обе линии наклонные) |

**Шаг 3. Применить решающие правила (по порядку).**

```
1. Если плато есть:
       если Кр(М) и Пд(М): form_type = cylinder
       если Кр(Н) и Пд(М): form_type = trapezoid-top
       если Кр(М) и Пд(Н): form_type = trapezoid-bottom
       если Кр(Н) и Пд(Н): form_type = trapezoid-middle
       иначе: form_type = unknown-shape

2. Если плато нет:
       (тип определён через max_position)
       form_type = bell / funnel / v-shape
```

**Шаг 4. Постпроверка.**

Если структура не подошла ни под одно правило (например,
экстремум не нашёлся, порядок элементов нарушен, плато
расположено нестандартно) — `unknown-shape`.

### 7.4. Пограничные случаи и параметры

**Минимальная длина плато.** `min_plateau_thickness_tvdss`
(стартово 1 м). Плато короче — не выделяется, интервал
считается треугольником.


**Порог мгновенного перехода.** `boundary_frac` (стартово 0.15).
Граница короче 15% мощности — мгновенная; иначе — наклонная.

**Асимметричный v-shape / trapezoid-middle.** Если обе линии
плавные, но заметно разной длины — форма **остаётся** v-shape
(или trapezoid-middle). Симметричность фиксируется модификатором
`symmetry_top_bot`, но **не меняет тип**.

**Случай «обе мгновенные без плато».** Такой случай **невозможен
по построению**:
- Если обе границы `М`, каждая ≤ 0.15 мощности.
- Тогда на плато остаётся ≥ 1 − 0.15 − 0.15 = 0.70 мощности.
- Значит, плато есть, и это `cylinder`.

Если алгоритм всё же выдаёт структуру `Кр(М) | – | Пд(М)` —
это баг или нестандартный случай, уходит в `unknown-shape`.

### 7.5. Про unknown-shape

`unknown-shape` — это **не свалка**, а **осмысленный сигнал**.
В него попадают аномалии, структура которых не соответствует
ни одному шаблону.

**Три роли unknown-shape:**

1. **Проверка работы алгоритма.** Если на выборке доля
   unknown-shape < 10% — методика работает. Если > 30% —
   что-то не так.

2. **Индикатор новых форм.** Если unknown-shape систематически
   возникают на похожих интервалах — возможно, это новая форма.

3. **Отложенный анализ.** Интервалы с unknown-shape сохраняются
   со всеми признаками. Через несколько итераций можно
   пересмотреть их отдельно.

### 7.6. Все формы v3.0

Итого — **7 форм + unknown-shape**:

| # | Форма | Структура | Группа |
|---|---|---|---|
| 1 | bell | Кр(Н) ｜ – ｜ Пд(М) | треугольник |
| 2 | funnel | Кр(М) ｜ – ｜ Пд(Н) | треугольник |
| 3 | v-shape | Кр(Н) ｜ – ｜ Пд(Н) | треугольник |
| 4 | trapezoid-top | Кр(Н) ｜ + ｜ Пд(М) | трапеция |
| 5 | trapezoid-bottom | Кр(М) ｜ + ｜ Пд(Н) | трапеция |
| 6 | trapezoid-middle | Кр(Н) ｜ + ｜ Пд(Н) | трапеция |
| 7 | cylinder | Кр(М) ｜ + ｜ Пд(М) | прямоугольник |
| — | unknown-shape | не подходит ни под одну | — |

**Замечание про порядок.** В v2.x были формы
`bell / funnel / cylinder / trapezoid-middle / symmetric /
v-shape / uncertain`.

В v3.0:
- `trapezoid-top` и `trapezoid-bottom` **возвращаются** — со
  структурным подходом они различаются естественно (в v2.x их
  убрали из-за ненадёжного различения по трём опорам);
- `symmetric` **уходит** — его роль выполняет `v-shape`
  (структурно совпадают). Симметричность становится модификатором
  `symmetry_top_bot`;
- `uncertain` **заменяется** на `unknown-shape` с более осмысленной
  ролью.

**Про bell / funnel — важно.**
В v3.0 bell = лучший коллектор **внизу** (плавный вход, резкий
выход). funnel = лучший коллектор **вверху** (резкий вход,
плавный выход). Согласуется с классической геофизикой.

## 8. Модификаторы интервала

Модификаторы — признаки, описывающие интервал, но не относящиеся
к его форме напрямую.

| Модификатор | Значения | Что означает |
|---|---|---|
| `size_class` | small / medium / large / n/a | доля мощности интервала в контейнере |
| `position_in_container` | top / middle / bottom | положение интервала в пласте |
| `symmetry_top_bot` | symmetric / asymmetric-top / asymmetric-bot / n/a | симметрия кровли и подошвы |

### 8.1. size_class

Размер интервала — по доле в мощности родительского
пласта-контейнера. Уже работает в v2.x, не меняется.

```
relative = thickness_interval_tvdss / thickness_container_tvdss
small:  relative < 0.33
medium: 0.33 ≤ relative ≤ 0.67
large:  relative > 0.67
```

Пороги — в `config.yaml`, секция `size_classification`.

### 8.2. position_in_container

Положение центроида интервала внутри пласта. Уже работает
в v2.x, не меняется.

```
centroid_relative = (top_container − centroid_tvdss) /
                    (top_container − bottom_container)
top:    centroid_relative < 0.33
middle: 0.33 ≤ centroid_relative ≤ 0.67
bottom: centroid_relative > 0.67
```

### 8.3. symmetry_top_bot

Новый модификатор. Описывает симметрию кровли и подошвы
по длине. Осмыслен **только для форм с обеими плавными
линиями**: `v-shape` и `trapezoid-middle`.

| Значение | Условие |
|---|---|
| `symmetric` | ratio = top_length / bot_length ∈ [0.5, 2.0] |
| `asymmetric-top` | ratio > 2.0 (кровля существенно длиннее) |
| `asymmetric-bot` | ratio < 0.5 (подошва существенно длиннее) |
| `n/a` | для остальных форм, или если `bot_length ≈ 0` |

### 8.4. Что НЕ является модификатором интервала

- **`interbedded`** — это **состояние пласта**, не интервала
  (см. §9). Переслаивание внутри одного интервала описывается
  модификаторами элементов (`пологий` / `зубчатый`).
- **`trend`** — не вводим. Общий тренд интервала либо попадает
  в форму (через наклон линий), либо не важен.

## 9. Типы пласта

Уровень контейнера. Собирает результаты по всем интервалам пласта.

### 9.1. Состояние пласта — container_state

| Значение | Условие |
|---|---|
| `single-anomaly` | 1 интервал |
| `multi-anomaly` | 2–4 интервала, каждый ≥ 1 м |
| `interbedded` | 5+ интервалов, или ≥ половина < 1 м |
| `no-sand` | 0 интервалов (NTG = 0) |

Пороги 4 и 5 — стартовые, в `config.yaml`. Могут адаптироваться.

### 9.2. Метка типа — container_type

Формат зависит от состояния.

**single-anomaly и multi-anomaly:**

```
{N}-{form}-{size}-{position}
```

где:
- **N** — количество интервалов (1, 2, 3, 4);
- **form** — доминирующая форма **или** `mixed`, если в пласте
  больше одной формы;
- **size** — доминирующий размер;
- **position** — доминирующее положение.

**Правило `mixed`:**
- Если все интервалы имеют **одну форму** (например, все cylinder) —
  указывается эта форма.
- Если интервалы имеют **разные формы** (например, bell + cylinder) —
  форма в метке заменяется на `mixed`.

Примеры:
- `1-bell-medium-top` — один колокол;
- `2-cylinder-medium-top` — два цилиндра, все среднего размера,
  все в кровле;
- `2-mixed-medium-top` — два интервала с разными формами
  (доминирующая форма в `container_summary`).

**interbedded:**

```
{N}-interbedded-{size}-{position}
```

где:
- **N** — количество интервалов (все, включая микро);
- **size** — доминирующий размер (чаще всего small);
- **position** — доминирующее положение (по кластеру).

Пример: `7-interbedded-small-middle`.

**no-sand:**

```
no-sand
```

Без остальных частей. Просто «нет коллектора».

### 9.3. Расширенное описание пласта

Помимо короткой метки, для каждого пласта хранится:

- **`container_summary`** — текстовое описание (человеку):
  - `1 интервал: bell medium top (6.66 м)`
  - `2 интервала: bell medium top (5.50 м); cylinder small top (2.10 м)`
  - `7 интервалов переслаивания (все small), dominant position middle`
  - `нет коллекторов`
- **`container_intervals_json`** — JSON-массив с параметрами
  каждого интервала (форма, размер, положение, мощность,
  признаки элементов).

### 9.4. Доминирующие характеристики

Определяются по **суммарной мощности** интервалов (как в v2.x):

- доминирующая форма — сумма мощностей по каждой форме, максимум;
- доминирующий размер — то же;
- доминирующее положение — то же.

При близости (< 10% от общей мощности резервуаров) — тай-брейк
по `mean_confidence`. Параметр `container_type.dominance_margin`
в `config.yaml`.

## 10. Дискретный лог aSP_disc

### 10.1. Где живёт

**В `dataset.csv`** — отдельной колонкой `aSP_disc`. Считается
один раз, доступна всем модулям (сегментация, классификация
формы, литопрофиль).

Параллельно **экспортируется в LAS для Petrel** — как отдельная
кривая `ASP_DISC` (см. §12 и раздел про Petrel-экспорт).
Это нужно, чтобы геолог мог видеть дискретный лог рядом
с aSP прямо в Petrel.

### 10.2. Классы и границы

| Класс | Условие | Литология |
|---|---|---|
| 0 | aSP ≤ 0.2 | глина |
| 1 | 0.2 < aSP ≤ 0.4 | алевролит глинистый |
| 2 | 0.4 < aSP ≤ 0.6 | алевролит / песчаник |
| 3 | 0.6 < aSP ≤ 0.8 | песчаник среднезернистый |
| 4 | aSP > 0.8 | песчаник крупнозернистый |

Границы — `(lower, upper]`. Нижняя не включается, верхняя включается.

### 10.3. Минимальный интервал класса

Участок одного класса длиной < `min_class_thickness_tvdss`
(стартово 0.5 м) **присоединяется к соседу с большей мощностью**
(вариант «а», симметричное правило).

Если соседей двое — присоединяется к тому, у кого больше точек.
Если сосед только один — присоединяется к нему.

Параметр в `config.yaml`.

### 10.4. Роль дискретного лога

- **Быстрое выделение аномалий** — класс ≥ 2.
- **Поиск плато** — длинные участки одного класса (см. §7.3).
- **Определение контекста** — класс соседних с аномалией участков
  (см. §11).

**Дискретный лог не заменяет aSP.** Уточнение формы (типы границ,
тренды) идёт всегда **по сырому aSP**. Дискретный — вспомогательный.

## 11. Контекст неколлектора

### 11.1. Верхний и нижний контекст

Для каждой аномалии определяется, что за порода её подстилает
и перекрывает.

| Значение | Условие |
|---|---|
| `глина` | средний aSP соседнего участка ≤ 0.2 |
| `алевролит глинистый` | 0.2 < средний aSP ≤ 0.4 |
| `отсутствует` | аномалия начинается/кончается на кровле/подошве пласта |

Хранится два признака:
- `upper_context` — что **над** аномалией;
- `lower_context` — что **под** аномалией.

### 11.2. Определение соседнего участка

**Соседний участок** — это **интервал внутри пласта-контейнера,
непосредственно прилегающий к границе аномалии**:

- для верхнего контекста — от `top_tvdss` аномалии вверх до
  ближайшей границы (предыдущий non_reservoir интервал,
  или кровля пласта);
- для нижнего контекста — от `bottom_tvdss` аномалии вниз до
  ближайшей границы (следующий non_reservoir интервал,
  или подошва пласта).

Если между аномалией и границей пласта **нет** non_reservoir
(аномалия начинается сразу под кровлей или кончается на подошве) —
контекст = `отсутствует`.

### 11.3. Смешанный контекст

Если соседний участок **смешанный** (например, глина + алевролит):

- считать **средний aSP** по всему участку;
- относить к классу по среднему значению.

Если средний aSP в переходной зоне (например, ровно 0.3, между
«глина» и «алевролит глинистый») — берётся **ближайшая граница
сверху**, как в §10.2.

Отдельного значения `смешанный` **не вводим** — это усложняет
и без того непростую таксономию.

### 11.4. Что НЕ делаем

- **Контекст для всего интервала** (например, «перекрыт глиной
  со всех сторон») — не нужен. Достаточно upper/lower по отдельности.
- **Типизация самого неколлектора** — не делаем. Неколлектор
  в v3.0 описывается только как контекст аномалии.

Возврат к типизации неколлектора — возможен в v4.0, если
понадобится. Сейчас это отложено.

## 12. Параметры в config

Все параметры v3.0 — в `config.yaml`. Значения стартовые,
адаптируются по результатам на реальных данных.

### 12.1. Новая секция classification_v3

```yaml
classification_v3:
  # Версия правил.
  rules_version: "3.0"

  # --- Разбиение аномалии на элементы ---
  # Порог мгновенного перехода: граница короче этой доли
  # мощности интервала — мгновенная.
  boundary_frac: 0.15

  # Абсолютный порог мгновенного перехода (в метрах TVDSS).
  # Применяется, если доля от мощности даёт слишком длинную границу
  # для длинных интервалов.
  boundary_max_tvdss: 1.0  # Абсолютный порог мгновенного перехода (в метрах TVDSS)

  # Минимальная длина плато (в метрах TVDSS).
  # Плато короче — не выделяется, интервал считается треугольником.
  min_plateau_thickness_tvdss: 1.0

  
  # Минимальный средний aSP плато.
  # Плато с меньшим средним aSP не считается плато — это, скорее
  # всего, граница коллектора, а не песчаный уровень.
  min_plateau_asp: 0.5

  # --- Дискретный лог ---
  # Минимальная длина участка одного класса (в метрах TVDSS).
  # Короче — присоединяется к соседу с большей мощностью.
  min_class_thickness_tvdss: 0.5

  # --- Модификаторы элементов ---
  # Порог отклонения от локального среднего для детекции зубчатости
  # (в единицах aSP).
  zigzag_threshold: 0.05

  # Доля точек, превышающих порог отклонения, чтобы элемент считался
  # зубчатым.
  zigzag_fraction: 0.20

  # --- Плато ---
  # Диапазон «стабильности» вокруг локального среднего
  # (в единицах aSP). Плато — участок, где aSP не выходит за коридор.
  plateau_stability_range: 0.05

  # Порог тренда плато: если разница средних в начале и конце плато
  # больше этого значения — плато считается rising или falling.
  plateau_trend_threshold: 0.05

  # --- Форма ---
  # Допуск для классификации: если какой-то параметр не дотягивает
  # до порога, интервал уходит в unknown-shape.
  form_strict_mode: false
```

### 12.2. Обновлённая секция container_type

  multi_anomaly_min: 2      # минимум интервалов для multi-anomaly

Некоторые значения остаются **жёсткими в коде**, потому что они

- границы классов Муромцева (0.2 / 0.4 / 0.6 / 0.8) — стандарт;

- правило `max_position` для треугольников (через `boundary_frac`).

## 13. Открытые вопросы и планы пересмотра

Вопросы, которые **не решены окончательно** в v3.0. Все они
отложены до первых прогонов на реальных данных.

### 13.1. Детекция зубчатости (< 1 м)

Тонкое переслаивание (пички < 1 м) **не детектируется** в v3.0.
Модификатор `зубчатый` может работать частично на субпиксельных
колебаниях, но по-настоящему тонкие прослои мы не видим.

**Возможные решения в v3.1:**
- отдельный модуль детекции мелких пиков;
- введение признака «сложность линии» (число изменений знака производной);
- визуальный анализ с последующим добавлением эвристик.

**Что делаем сейчас:** фиксируем, не реализуем. Пилот покажет,
насколько это критично.

### 13.2. Уточнение контекста

Контекст описывается только как класс αПС (`глина` / `алевролит
глинистый`). Возможно, понадобится дополнить:

- мощностью соседнего участка (толстая глина vs тонкая);
- наличием переслаивания в контексте;
- градиентом перехода (резкий vs пологий).

**Решение:** посмотрим на пилоте, нужно ли. Возможно, оставим
как есть — контекст вспомогательный признак.

### 13.3. Смешанный контекст

Сейчас — по среднему aSP. Может быть, стоит вводить `смешанный`
как отдельное значение, если соседний участок имеет большую
внутреннюю изменчивость.

**Решение:** отложено.

### 13.4. Множественные плато

**Решение (обновлено 2026-10-02):**

- Все плато-кандидаты одного **доминирующего класса** объединяются
  в одно **интегральное плато**.
- Плато **других классов** не поглощаются: они становятся частью
  кровли (если выше доминирующего) или подошвы (если ниже).
- Доминирующий класс — по суммарной мощности плато-кандидатов.
  Тай-брейк — по среднему aSP (выше = доминирует).
- Детализация сохраняется: `n_plateaus`, `plateau_segments_json`.
- В `unknown-shape` множественные плато **не отправляют**.

**Обоснование.** Если внутри аномалии два плато одного класса,
разделённые коротким пропластком, — это одна трапеция (или
прямоугольник) с «дыркой», а не неопознанная форма. Форма
определяется по интегральному плато; детали сохраняются в
признаках, доступных для анализа.

Если плато разных классов — доминирующий класс выигрывает, а
плато другого класса становится частью границы. Это осмысленно:
например, верхняя часть аномалии — плато класса 3 (чистый
песок), нижняя — плато класса 2 (алевролит). Нижняя часть
трактуется как наклонная подошва.

### 13.5. Формат `aSP_disc` в Petrel-выгрузке

Кривая `ASP_DISC` будет добавлена в LAS для Petrel. Формат:
- целые числа 0–4;
- NULL для точек вне рабочего интервала.

**Уточнить после первого экспорта.**

### 13.6. Модификаторы элементов — расширение

Возможно, в будущем понадобится больше модификаторов:
- `плавный` (полностью гладкая линия);
- `ступенчатый` (несколько мелких плато).

**Решение:** отложено. Сейчас только `пологий` / `зубчатый`.

### 13.7. `container_state` — пересмотр порогов

Пороги 4 (multi-anomaly max) и 5 (interbedded min) — стартовые.
Могут быть пересмотрены после пилота.

### 13.8. Адаптация порогов под выборку

Все стартовые значения (0.15, 0.70, 0.5 м, 1.0 м) — гипотезы.
После прогона на 5–10 скважинах может потребоваться их
корректировка.

**Принцип:** менять **только те пороги**, которые дают системную
ошибку. Не подгонять под отдельные интервалы.

## 14. План внедрения

v3.0 — не откат v2.x, а **параллельная система**. Внедряем
постепенно, с возможностью отката.

### 14.1. Этапы

**Этап 1. Пилот на 227_2263.**

- Реализуем v3.0 как **отдельный модуль** `src/domain/classify_form_v3.py`.
- Прогоняем на 7 интервалах пилотной скважины.
- Смотрим результат **глазами геолога**: сравнение формы из алгоритма
  с тем, что видно на планшете.
- **Старый `classify_form.py` не трогаем** — работает параллельно.

**Формат проверки (этап 1):**

1. Запустить v3.0 на 227_2263.
2. Вывести таблицу: `layer_name`, `interval_index`, `form_v3`,
   `container_summary_v3`, ключевые признаки элементов.
3. Геолог смотрит планшет и результат рядом. Фиксирует расхождения
   устно/в отдельном файле.
4. По результатам — либо продолжаем (если расхождений мало), либо
   уточняем правила.

**Без формальной разметки на этом этапе.** Ручная разметка
геологом — на этапе 3 (после набора выборки).

**Этап 2. Сравнение.**

- Прогоняем на всех 5 скважинах.
- Сравниваем `form_type` между v2.x и v3.0.
- Анализируем расхождения: где v3.0 лучше, где хуже.

**Этап 3. Калибровка.**

- Смотрим `unknown-shape` — сколько и на чём.
- Уточняем пороги (не подгоняем под интервалы, а ищем системные
  проблемы).
- Возможно, уточняем правила.

**Этап 4. Раскатка.**

- Если v3.0 устойчиво работает — постепенно заменяем вызовы
  v2.x на v3.0.
- Визуализация (`well_log.py`) обновляется под новые формы.
- Легенда форм (`form_legend.py`) обновляется.
- Petrel-выгрузка: добавляется `ASP_DISC`.

**Этап 5. Отказ от v2.x.**

- После стабилизации v3.0 — удаляем `classify_form.py` (v2.x),
  переименовываем `classify_form_v3.py` → `classify_form.py`.
- Версия правил поднимается до `"3.0"` в `config.yaml`.

### 14.2. Что НЕ трогаем в v3.0

- Сегментация (`segmentation.py`) — работает как есть.
- Нормализация (`normalization.py`) — работает как есть.
- Размер и положение (`size_class.py`) — работает как есть.
- `container_type.py` — обновляется только под новые метки (§9),
  логика доминирования сохраняется.
- Petrel-выгрузка — добавляется кривая `ASP_DISC`, остальное
  без изменений.

### 14.3. Что нужно для старта

1. **Добавить секцию `classification_v3`** в `config.yaml`.
2. **Обновить `container_type`** в `config.yaml`.
3. **Реализовать `classify_form_v3.py`** — новый модуль.
4. **Добавить `aSP_disc`** в `build_dataset.py` (расчёт колонки).
5. **Запустить пилот** на 227_2263.
6. **Сравнить** с текущими результатами v2.x.

#### 14.4. Критерии успеха v3.0

**На этапе 1 (пилот, 7 интервалов, 1 скважина):**

- Алгоритм **запускается без ошибок** на всех 7 интервалах.
- **≥ 5 из 7 форм** совпадают с тем, что геолог видит глазом.
- Формы **объяснимы**: геолог может сказать «да, тут действительно
  наклонная кровля и мгновенная подошва».
- `unknown-shape` — не более 2 из 7 (≤ 30%).

**На этапе 2 (5 скважин, 30 интервалов):**

- Стабильность: одна и та же форма в схожих условиях
  воспроизводится (bell не превращается в funnel между скважинами).
- `unknown-shape` ≤ 30% от всех интервалов.

**На этапе 3 (после ручной разметки 30+ интервалов):**

- **Совпадение с ручной разметкой ≥ 70%** по форме.
- Понятна структура ошибок: где и почему алгоритм ошибается.
- Есть план по улучшению (v3.1) или подтверждение, что v3.0
  достаточно хорош для раскатки.

Если на любом этапе критерии не выполнены — пересматриваем
правила v3.0, не катим дальше.
