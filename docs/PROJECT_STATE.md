# Состояние проекта ps_electrofacies

**Дата снимка:** 2026-09-28
**Текущий шаг:** техническая ревизия под батч-обработку
**Следующий шаг после ревизии:** H — сопоставление пластов между скважинами

## 1. Что это за проект

Разработка программы для типизации кривых ПС методом электрофациального
анализа. Пилот на одной скважине, в перспективе — обработка выборки
(до 1000 скважин) с выходом на типизацию пластов и картирование.

**Конечная цель:** для каждого пласта (БС9, БС10-1, …) в каждой
скважине получить одну строку со всеми характеристиками и научиться
сопоставлять одноимённые пласты между скважинами (см. ADR-003).

**Пользователь:** геолог-петрофизик, новичок в программировании, учится
«вайбкодингу с умом». Нужны подробные комментарии в коде и методике,
сначала документ — потом код.

**Стек:** Python 3.14, VS Code, Git/GitHub. Библиотеки: numpy, pandas,
matplotlib, lasio, openpyxl, pyyaml.

## 3. Ключевые методические решения

**Глубины и мощности:**
- Мощности — по TVDSS (абсолютные отметки), не по MD. TVDSS
  в Petrel-стиле: отрицательные значения вниз (KB − TVD).
- Разметка точек пласта — по MD.
- Ось Y на графике — TVDSS.
- MD → TVDSS — линейная интерполяция через `.dev`.

**Нормализация:**
- SP_norm и GK_norm в диапазон [0, 1]: 0 = чистый песок, 1 = глина.
- Считается внутри рабочего интервала (от первой кровли до конца .dev).
- Перцентили 5 и 95 для опорных линий.

**Сегментация:**
- Порог коллектора SP_norm < 0.6 (αПС > 0.4 по Муромцеву).
- Сглаживание SP_norm: окно 5 точек (0.5 м).
- Микроинтервалы < 1 м присоединяются к соседним.

**Классификация формы (v2.0, ADR-001):**
- 6 типов: bell, funnel, cylinder, trapezoid-middle, symmetric,
  uncertain.
- Опорные точки — средние по 15% мощности интервала
  (sp_top, sp_mid, sp_bot).
- Пороги: threshold_diff=0.20, plateau_threshold=0.10,
  slope_threshold=0.20, core_threshold=0.05.
- Доработка критериев отложена до шага H (ADR-002).

**Размер и положение (шаг E):**
- Размер — по доле мощности интервала в мощности родительского
  контейнера: small < 0.33, medium 0.33–0.67, large > 0.67.
  Пороги фиксированные (не перцентили выборки).
- Положение — по относительному положению центроида в контейнере:
  top < 0.33, middle 0.33–0.67, bottom > 0.67.
- Центроид — среднее по точкам интервала, не середина по границам.

**Сводная типизация (шаг F, ADR-004):**
- Одна строка на пласт-контейнер в `features.csv`.
- Доминирующая характеристика — по суммарной мощности; при близости
  (< 10% от общей мощности резервуаров) — по confidence.
- Формат: `container_type` (короткая метка) + `container_summary`
  (текстовое описание) + `container_intervals_json` (JSON-массив).
- NTG = 0 → `no-sand`.

**Единица анализа (ADR-003):**
- Пласт-контейнер, а не разрез скважины.
- Типизация разреза скважины целиком — не делается.

## 6. Ограничения и известные особенности

- **Классификация формы на пилоте не идеальна.** Часть интервалов
  отнесена к формам, не совпадающим с ручной интерпретацией геолога.
  Это осознанно зафиксировано в ADR-002 и будет уточняться после
  накопления 5+ скважин с ручной разметкой.
- **Переслаивание (M-форма)** не разрезается на сегментации.
  Такие интервалы идут в `uncertain`.
- **Не все интервалы получают `large`** при текущих порогах размера —
  коллекторы обычно занимают малую долю мощности пласта. Это
  корректно, но стоит держать в голове при обсуждении результата.
- **Одна скважина — не выборка.** Все категории (форма, размер,
  положение, container_type) на пилоте отражают одну точку данных.

## 7. Дорожка дальше

**Ближайший шаг:** техническая ревизия под батч-обработку.

Задачи ревизии:
1. Структура входных данных: список скважин вместо одной.
   Файлы по шаблону `data/raw/{las,deviation,markers}/<well_name>.*`.
2. Структура выходных данных: папки
   `data/processed/<well_name>/` с dataset, intervals, features, plot.
3. Батч-запуск: `process_well(well_name)` + цикл по списку.
4. Сводная таблица `data/processed/summary_all_wells.csv` — одна
   строка на пласт в каждой скважине для шага H.
5. Отчёт по каждой скважине (короткий), чтобы видеть сбои.

**После ревизии:**
- Добавляем 2–3 скважины для проверки устойчивости пайплайна.
- Шаг H: сопоставление одноимённых пластов между скважинами,
  кластеризация, карты.
- Возврат к доработке критериев классификации формы (ADR-002) —
  при накоплении ≥ 5 скважин с ручной разметкой.
