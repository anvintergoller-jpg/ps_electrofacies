## 1. Что это за проект

Разработка программы для типизации кривых ПС методом
электрофациального анализа. Пилот расширен до 5 скважин,
в перспективе — обработка выборки (до 1000 скважин) с выходом
на типизацию пластов и картирование.

**Конечная цель:** для каждого пласта (БС9, БС10-1, …) в каждой
скважине получить одну строку со всеми характеристиками и уметь
сопоставлять одноимённые пласты между скважинами (см. ADR-003).

**Пользователь:** геолог-петрофизик, новичок в программировании,
учится «вайбкодингу с умом». Нужны подробные комментарии в коде
и методике, сначала документ — потом код.

**Стек:** Python 3.14, VS Code, Git/GitHub. Библиотеки: numpy,
pandas, matplotlib, lasio, openpyxl, pyyaml.

## 3. Ключевые методические решения

**Глубины и мощности:**
- Мощности — по TVDSS (абсолютные отметки), не по MD.
- Разметка точек пласта — по MD.
- Ось Y на графике — TVDSS.

**Нормализация (ADR-006, ADR-007):**
- aSP (alpha-PS): 0 = глина, 1 = песок.
- GK_norm: 0 = песок, 1 = глина.
- Перцентили **2 / 98** (граничные, устойчивы к выбросам,
  близко к min/max как в Petrel).
- Считаются для каждой скважины **отдельно**, внутри рабочего
  интервала (от верхней отбивки до конца .dev).
- Сглаживание исходной SP **не применяется**.

**Сегментация:**
- Порог коллектора `aSP > 0.4` (Муромцев, αПС = 0.4).
- Сглаживание aSP: окно 5 точек (0.5 м), параметр
  `preprocessing.smooth_window`.
- Микроинтервалы < 1 м присоединяются к соседним.

**Классификация формы (v2.0, ADR-001):**
- 7 типов: bell, funnel, cylinder, trapezoid-middle, symmetric,
  v-shape, uncertain.
- Опоры — средние по 15% мощности интервала.
- Ключевой признак `frac_core` разделяет trapezoid-middle /
  symmetric / v-shape.
- Доработка критериев отложена до набора выборки (ADR-002).

**Размер и положение (шаг E):**
- Размер — доля мощности интервала в мощности контейнера:
  small < 0.33, medium 0.33–0.67, large > 0.67.
- Положение — по относительному положению центроида:
  top < 0.33, middle 0.33–0.67, bottom > 0.67.
- Пороги фиксированные (не перцентили выборки), чтобы сравнивать
  между скважинами.

**Сводная типизация (шаг F, ADR-004):**
- Доминирующая характеристика — по мощности; при близости
  (< 10%) — по confidence.
- Формат: `container_type`, `container_summary`,
  `container_intervals_json`.
- NTG = 0 → `no-sand`.

**Единица анализа (ADR-003):**
- Пласт-контейнер, а не разрез скважины.

**Батч-обработка (ADR-005):**
- Список скважин: `wells: "auto"` или явный список.
- Пути через шаблоны `{well}`.
- Выход: `data/processed/<well_name>/` + сводка
  `summary_all_wells_<ts>.csv` + общий лог.

**Ревизия H.5 (ADR-008):**
- Единый источник параметров: `preprocessing`, `reservoir`.
- Убраны дубли `cutoff`, `smooth_window`, `min_thickness_tvdss`.
- Убраны скрытые дефолты в `ClassificationParams`.
- Убраны legacy-пути и секция `logging`.
- Создан `docs/ARCHITECTURE.md` — карта модулей.

## 6. Ограничения и известные особенности

- **Классификация формы не идеальна.** Часть интервалов
  отнесена к формам, не совпадающим с ручной интерпретацией
  (ADR-002).
- **Много `uncertain`** — следствие того, что пороги формы
  калибровались на ранних данных и не пересчитывались после
  перехода на aSP (2/98).
- **Категория `large` не встречается** при текущих порогах
  размера — коллекторы обычно занимают малую долю пласта.
- **5 скважин — не выборка.** Все категории отражают одну
  локальную точку (район вокруг 227_2263).
- **Overfitting риск.** Донастройка порогов на 5 скважинах
  одного района приведёт к переобучению. Поэтому критерии
  заморожены.

## 6.5. Классификация v3.0 — в разработке

С 2026-10-01 ведётся полная переработка методики классификации
формы. Причина — v2.x привязана к трём опорам и порогам,
откалиброванным под выборку.

**Документ:** `docs/CLASSIFICATION_RULES_v3.md` (черновик готов).

**Ключевое:**
- Структурный подход: аномалия = кровля + плато + подошва.
- 7 форм + unknown-shape.
- Новые ключевые признаки: `max_position`, `aSP_disc`,
  `plateau_trend`, `symmetry_top_bot`.
- Дискретный лог `aSP_disc` — 5 классов Муромцева.

**Статус:** методика готова, реализация — следующий шаг.
Планируется отдельный модуль `classify_form_v3.py` (параллельно
с текущим `classify_form.py`).

**План проверки:** пилот на 227_2263 → 5 скважин → ручная
разметка → возможная калибровка v3.1.
